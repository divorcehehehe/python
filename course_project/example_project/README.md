# Образец курсового проекта: игра «Угадай число»

Крошечная рабочая программа, которая показывает **структуру**, обязательную для
курсового проекта: точка входа `main.py`, классы предметной области в папке
`models/` по файлу на класс, данные в JSON-файле. Тема выбрана намеренно вне
списка тем курсового: сдать этот проект как свой не получится, его можно только
разобрать и повторить приёмы.

Программа спрашивает уровень, загадывает число и даёт несколько попыток. После
партии результат попадает в таблицу рекордов `records.json`, на экран печатается
топ-3.

## Два уровня сложности

При запуске программа спрашивает: «Уровень: 1 обычный, 2 сложный?».

| Уровень | Класс | Диапазон | Попыток |
|---|---|---|---|
| обычный | `Game` в `models/game.py` | 1–100 | 7 |
| сложный | `HardGame` в `models/hard_game.py` | 1–1000 | 10 |

Любой ответ кроме `2` считается обычным уровнем: игрока не мучают повторным
вопросом. `HardGame` наследуется от `Game` и меняет только константы класса
`LEVEL`, `MAX_ATTEMPTS`, `HIGH` и метод `__str__` — весь код правил
(`guess`, `is_over`, `attempts_left`) достаётся ему от родителя без единой
скопированной строки. Это и есть наследование с полиморфизмом: строка
`game = level(player)` в `main.py` одинаково создаёт объект любого из двух
классов, а дальше `main.py` не знает и не спрашивает, с каким уровнем работает.

Обратите внимание на `HardGame.__str__`: он вызывает `super().__str__()` и
дописывает к строке родителя своё, а не собирает её заново.

## Как запустить

**В PyCharm.** File → Open, выбрать папку `example_project` (именно её, не папку
курса). Открыть `main.py`, нажать правой кнопкой по редактору → Run 'main' или
Shift+F10. Внешние библиотеки не нужны, хватит любого Python 3.10 и новее.

**В терминале Windows.**

```
cd путь\к\example_project
python main.py
```

Запускать нужно из папки `example_project`: иначе Python не найдёт пакет
`models`. Файл `records.json` при этом ищется не по рабочей папке, а рядом с
`main.py` (см. `models/records.py`), поэтому рекорды не потеряются.

## Что где лежит

```
example_project/
    main.py              сборка объектов и игровой цикл
    records.json         данные: таблица результатов, изначально пустой список
    README.md            этот файл
    models/
        __init__.py      делает папку пакетом, поэтому работает import
        player.py        Player: имя игрока и счётчик его попыток
        game.py          Game: загаданное число, подсказки, конец партии
        hard_game.py     HardGame(Game): сложный уровень, 1–1000 и 10 попыток
        display.py       Display: весь вывод на экран и ввод с клавиатуры
        records.py       Records: чтение и запись records.json
```

Ответственность разделена так, чтобы каждый класс отвечал за одно. `Game` не
печатает и не спрашивает, `Display` не знает правил игры, `Records` не знает,
кто такой игрок. Собирает их вместе только `main.py`.

Счётчик попыток живёт ровно в одном месте — в `Player`. Увеличить его можно
только методом `player.add_attempt()`, прочитать — через property `attempts`
только для чтения. `Game` своего счётчика не заводит: он получает игрока в
`__init__` (это композиция, «игра содержит игрока») и сравнивает
`self.player.attempts` со своей константой `MAX_ATTEMPTS`. Поэтому два числа
никогда не разъезжаются.

## Какое требование чем закрыто

| Требование курсового | Где выполнено |
|---|---|
| Консольная программа доведена до рабочего состояния | запускается одной командой, партия доходит до конца |
| Не меньше трёх классов предметной области, каждый в своём файле в `models/` | `Player`, `Game`, `HardGame`, `Display`, `Records`: пять файлов в `models/` |
| Точка входа `main.py` с `if __name__ == '__main__'` | две последние строки `main.py` |
| В каждом классе `__str__` | `Player.__str__`, `Game.__str__`, `HardGame.__str__` (через `super()`), `Display.__str__`, `Records.__str__` |
| Защищённые поля | `_name`, `_attempts`, `_player`, `_secret`, `_won`, `_rows`, `_path` |
| Хотя бы одно `@property` с проверкой в setter | `Player.name`: setter не принимает пустое имя, поднимает `ValueError` |
| Свойства только для чтения | `Player.attempts`, `Game.player`, `Game.secret`, `Game.is_won`, `Game.is_over`, `Game.attempts_left` |
| **На выбор (а): наследование с полиморфизмом** | `models/hard_game.py`: `class HardGame(Game)` переопределяет константы класса и `__str__`; `main.py` создаёт объект строкой `game = level(player)` и дальше работает с обоими классами одинаково |
| Обработка ошибок ввода: программа не падает | `Display.ask_number` (не число — повтор, число вне 1–N — повтор без траты попытки), `ask_player` в `main.py` (ловит `ValueError` от `Player`), `except EOFError` в `main` на случай конца ввода |
| Данные хранятся в файле (txt или json) | `records.json`, работа с ним в `models/records.py` через `json` и `pathlib` |
| Без глобальных переменных, константы ЗАГЛАВНЫМИ | константы класса `LEVEL`, `MAX_ATTEMPTS`, `LOW`, `HIGH` в `Game` и `HardGame`; `FILE_NAME`, `TOP_SIZE` в `models/records.py` |
| Имена по PEP 8 | классы `CapWords`, функции и переменные `snake_case`, отступ 4 пробела |

Константы игры сделаны атрибутами класса, а не модуля, именно ради наследования:
наследнику достаточно написать `HIGH = 1000`, и родительский код сразу считает
по новому числу, потому что обращается к ним как `self.HIGH`.

Про таблицу рекордов: записывается результат каждой законченной партии вместе с
уровнем, строки отсортированы по возрастанию попыток. Проигравший всегда тратит
все попытки, поэтому он оказывается внизу с пометкой «не угадал». Уровни в
таблице не разделены: одна попытка на сложном стоит дороже, чем на обычном, —
если это мешает, отсортируйте или отфильтруйте по полю `level` в
`models/records.py`.

## Чего в образце нет специально

Пункт «на выбор» из обязательного минимума закрыт вариантом (а): наследование с
полиморфизмом, `models/hard_game.py`. Вариант (б) — внешняя библиотека — не
использован намеренно: образец должен запускаться сразу после установки Python,
без `pip install`. В своём проекте можно закрыть оба варианта (это отдельно
повышает оценку): добавьте, например, `rich` для цветного вывода и не забудьте
`requirements.txt`.

## Переменная окружения GUESS_SECRET: приём для тестов

Программа со случайным числом неудобна для проверки: заранее неизвестно, что
вводить. Поэтому `Game.__init__` сначала загадывает `random.randint(1, 100)`, а
потом смотрит переменную окружения `GUESS_SECRET` и, если она задана, берёт
число из неё. Так партию можно проиграть по заранее написанному сценарию.

В терминале Windows:

```
set GUESS_SECRET=25
python main.py
set GUESS_SECRET=
```

В Linux или macOS достаточно одной строки: `GUESS_SECRET=25 python3 main.py`.
Приём полезный, но не обязательный: в своём проекте так же можно фиксировать
случайное слово или порядок вопросов, чтобы проверять программу без гадания.
